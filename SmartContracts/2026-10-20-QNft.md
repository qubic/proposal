# Proposal to Include the QNFT Smart Contract

## Proposal

Include **QNFT**, a smart contract for creating, holding and trading NFTs represented by native Qubic assets, in Qubic Core.

QNFT combines collections, metadata, fixed editions, a built-in marketplace and shareholder governance. Owners can transfer their NFTs or move management of their assets to compatible Qubic contracts. Existing QBay owners can also migrate their NFTs to this asset-based model through a one-way import.

The implementation uses existing QPI asset functionality. It requires normal contract registration and deployment, but no new asset type or changes to Qubic's asset ledger.

## Available Options

- **Option 0: No — do not include QNFT.**
- **Option 1: Yes — include QNFT with the functionality and initial economics described in this proposal.**

## Why QNFT

An NFT stored only as a record inside one application depends on that application's transfer and marketplace procedures. A QNFT item has a native asset identity, allowing its units to participate in compatible asset workflows across Qubic.

The owner can keep an NFT, send it to another person, sell it through the QNFT shop, or transfer its management to another accepting contract. Moving management preserves the native asset's identity and its association with the metadata recorded in QNFT.

For example, an owner can move ten copies of an edition to QX and offer them for QU, while keeping the remaining copies under QNFT management. QX supports asset buy and sell orders, including partial fills. This uses QX's own trading rules and fees. See the [QX documentation](https://docs.qubic.org/learn/qx/).

Compatibility depends on the receiving contract accepting and supporting the asset. NFT artwork display still requires wallets and applications to read QNFT metadata.

## Collections, Issuance and Ownership

A creator first creates a collection with a description and limits on its items and total units. The collection administrator can then issue items into that collection:

- **Unique artwork:** one item, one native asset, one unit.
- **Limited edition:** one item, one native asset, 100 identical units sharing the same metadata.
- **Collection of different artworks:** 100 items, each represented by a separate asset.

An edition's copies do not have separate serial numbers. Once an item is issued, QNFT cannot increase its original supply. Burning units reduces the outstanding quantity without reopening issuance capacity.

QNFT is the issuer of the assets. Each item receives a distinct asset name, while the original creator is recorded separately. Ownership and balances are held in the native Qubic asset ledger. Collection membership, creator attribution, metadata references and royalties are held in QNFT state.

Owners may appoint an operator for a particular item. The operator can transfer, burn or export the owner's available units of that item. This permission remains active until the owner revokes it or replaces the operator; it does not grant control over every item the owner holds.

## Metadata

Creators can choose immutable metadata, metadata managed by a designated editor, or metadata committed in advance for a later reveal. Revealing committed metadata permanently freezes it. Editable metadata can also be frozen.

QNFT stores the metadata URI and content hash. The referenced metadata document and media remain in external storage, such as IPFS. Creators remain responsible for making that content available.

These features support artwork, collectibles, membership editions and game items. Any membership benefits or game behavior must be implemented by the applications using those NFTs.

## Built-in Marketplace

The QNFT shop supports fixed-price listings and purchases of all or part of an edition. Listed units are held in escrow, and sellers can cancel the unsold portion.

The initial shop commission is **2% of the purchase price**. Optional creator royalties are deducted separately. A missing royalty recipient means no royalty is charged. The seller and royalty recipient are paid during the purchase; unsuccessful QU transfers are recorded for automatic retry.

For a sale of 10,000 QU with a 5% royalty, the shop collects 200 QU, the creator receives 500 QU and the seller receives 9,300 QU.

QNFT does not enforce its shop commission or royalties on trades executed through other contracts.

## One-way Migration from QBay

QBay owners can bring existing NFTs into a QNFT collection:

1. Create a QNFT collection or use one they are authorized to issue into.
2. Prepare an import request identifying the original NFT and the beneficiary.
3. Transfer the original NFT to QNFT through QBay after clearing its active marketplace conditions.
4. Finalize the import. QNFT verifies custody, creates a native asset with one unit and delivers it to the recorded beneficiary.

Preparing a request does not issue an item. The item is created during finalization, preserving the original creator, royalty and metadata reference. If delivery of the issued asset fails, QNFT retries it automatically on subsequent ticks.

**Migration is irreversible.** The original remains in QNFT custody inside QBay; there is no return or administrator rescue procedure. Users must prepare a valid request before depositing the original. A cancelled request must not be followed by a deposit.

## Initial Fees

All amounts below are in QU. Fixed fees apply per successful operation, not per edition copy.

| Operation | Initial fee |
| --- | ---: |
| Create a collection | 1,000,000 QU |
| Mint an item, including a multi-copy edition | 100,000 QU |
| Nominate a new collection administrator | 10,000 QU |
| Transfer NFT units | 10,000 QU |
| Approve an operator | 10,000 QU |
| Update editable metadata | 50,000 QU |
| Export asset management | 10,000 QU, plus any destination charge |
| Prepare a QBay import | 100,000 QU |
| Create a shop listing | 10,000 QU |
| Buy through the shop | 2% of the purchase price |
| Submit or replace a shareholder proposal | 1,000,000 QU |

There is no QNFT fee for revoking an operator, burning units, cancelling a listing or import request, claiming an undelivered mint, accepting an administrator nomination, revealing or freezing metadata, finalizing an import, or casting shareholder votes. Cancelling a proposal is also free.

Creating a collection and minting an edition of 100 identical copies therefore costs **1,100,000 QU**. Creating a collection and minting 100 distinct items costs **11,000,000 QU**.

Excess payment is refunded. Rejected calls return available refundable payment; a fee already consumed by a destination contract cannot be refunded again. Failed refunds are retried automatically. Cancelling a successfully prepared import does not reimburse its preparation fee.

## Revenue Distribution

Protocol fees accumulate throughout the epoch and are distributed at its end:

| Recipient or purpose | Initial allocation |
| --- | ---: |
| Developer | 20% |
| QNFT shareholders | 60% |
| Burn into the contract execution reserve | 20% |

Seller proceeds, creator royalties and refundable user funds are excluded from this revenue pool.

The developer receives a direct payment, shareholders receive dividends through Qubic's distribution mechanism, and the burn allocation replenishes the execution reserve. Dividend rounding remainders are carried forward. Failed payments remain accounted for without paying successful portions twice.

The starting fees are policy choices, not NFT-standard requirements or a promise of profitability. Actual reserve consumption and usage should inform future shareholder decisions.

## Shareholder Governance

QNFT shareholders can propose and vote on fee changes using Qubic's built-in proposal mechanism. Voting rights come from QNFT contract shares, not from ownership of NFTs.

Shareholders can change all of the following:

| Parameter | Initial value |
| --- | ---: |
| Collection creation fee | 1,000,000 QU |
| Item minting fee | 100,000 QU |
| Shop commission | 2% |
| Shareholder revenue allocation | 60% |
| Execution-reserve burn allocation | 20% |
| Administrator nomination fee | 10,000 QU |
| Transfer fee | 10,000 QU |
| Operator approval fee | 10,000 QU |
| Metadata update fee | 50,000 QU |
| Export fee | 10,000 QU |
| Import preparation fee | 100,000 QU |
| Listing fee | 10,000 QU |
| Proposal submission fee | 1,000,000 QU |

One proposal can change several parameters together. Accepted changes take effect after the closing epoch's revenue distribution.

**The developer allocation remains fixed at 20%.** Shareholders can redistribute the remaining 80% between dividends and burning; those two allocations must remain complementary.

Fixed fees may be set to zero or any supported monetary amount. The shop rate may range from 0% to 100%. There is no additional affordability cap imposed on shareholder decisions. Applications should retrieve current fees before submitting transactions.
